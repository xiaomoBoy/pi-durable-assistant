# Pi Durable 发布前审计与当前阶段冻结意见（2026-10-10）

> 范围：截至本记录时的 `main`、PR #4（Obsidian 知识检索）、PR #5（受控工作区与审批）、PR #6（F3 通知 Outbox）及固定上游的微信 iLink 适配。**代码静态审查 + GitHub CI 模拟测试；未登录用户 VPS、真实模型或微信。**

## 结论

**可以停止新增功能，进入稳定性验收阶段。** 当前没有证据表明必须重写前端、后端或持久执行框架。但不能把“单元/模拟端到端测试通过”理解为“生产数据安全已验证”。在没有可恢复备份前，不建议把此版本当作长期唯一事实源，也不要用它保存无法恢复的重要资料。

架构层的优势：单用户原生 ESM + Pi Durable Document/Task/SQLite 持久事务；HTTP/SSE 简单清晰；提醒与周期任务跨进程恢复；微信入站幂等与独立 Outbox；Docker read-only 根文件系统和非 root 运行；公开网页抓取对 DNS 解析与公网 IP 设有约束；Agent 文件写入采用人工审批且与 Obsidian 权威源隔离。

## 审计发现和修复

| 严重度 | 位置 | 发现 | 处理 |
| --- | --- | --- | --- |
| **中 / 前端容错** | `public/v3.js` | 核心任务管理与可选审批、文件、通知接口使用同一 `Promise.all`，任一可选接口暂时失败会让整个任务中心刷新失败 | PR #5、#6：可选接口独立降级，核心任务仍可操作；页面明确显示附加区域不可用 |
| **高 / 审批数据恢复** | `lib/actions.mjs` | 写入完成回调对失败状态也清空已审批正文；临时磁盘问题或同名文件冲突后无法再执行同一审批 | PR #5、#6：仅成功落盘后清空正文；失败保留原批准内容，提供登录后显式 `POST .../retry` 与任务中心按钮，不能借此修改目标或正文 |
| **中 / 通知误判** | `lib/notifications.mjs` | 飞书机器人可能 HTTP 200 但 JSON 的 `code`/`StatusCode` 非 0；按 HTTP 状态判断会错误标记已发送 | PR #6：应用层 code 必须为 0；否则保留待重试状态，不再误报成功 |
| **已知设计限制** | 微信/通用通知 | 接收方返回成功而本地尚未标记成功时崩溃，可能重复投递 | 稳定事件 ID + 至少一次尝试语义；第三方端到端恰好一次无法单方面保证 |
| **已知设计限制** | `lib/workspace.mjs` | 文件工作区不是命令沙箱；目录由运营者指定，若错误地挂载宿主敏感目录会扩大访问面 | 默认关闭 + 独立 Docker 命名卷；禁止任意 Shell；不宣称实现宿主隔离 |

## 分项审计

### 后端

- 检查 HTTP Basic Auth、非 GET 同源请求验证、生产模拟崩溃开关、Webhook Bearer Auth；管理 API 不应暴露在绕过 TLS 的公网接口上。
- 核对 Durable 事务内入队；业务提交和通知持久化保持同一事务，外部 HTTP 在事务外执行；出站延迟、失败和反复发送有上限。
- 检查工作区文件路径、隐藏目录/符号链接、固定扩展名、审批去重；当前没有任意 Shell 执行工具。
- 微信 `wx-bot` 供应链固定 commit + 严格补丁；上游文档明确 `allow_wxids: []` 默认仅允许扫码账号自己，并非默认开放所有微信联系人；真实扫码/权限仍需现场确认。
- Obsidian PR #4 默认只读白名单，禁止 `my-info` 及敏感目录，归档/草稿需单独标记；**它尚未合并，也未经过真实仓库挂载验收。**

### 前端

- `public/index.html` 是单文件聊天界面（含 CSS/JS）；`public/v3.js` 是独立管理抽屉。代码体积偏大但不是阻断项，不值得现在更换框架。
- 用户消息、工具结果、会话名经过 HTML 转义；Markdown 链接只允许 HTTP(S) 正常展示。模型输出绝不应该被当作可信 HTML/脚本执行。
- 修改任务中心仅限容错与已审批失败恢复，不重构主聊天布局。缺少自动浏览器兼容性测试，因此 Safari/iOS、长对话 SSE 的真实 UI 行为仍需人工确认。

### 部署与状态安全

- **正式长期运行的唯一明确发布条件**：实际可恢复的 SQLite 数据卷备份，并验证恢复；否则磁盘损坏或错误删除卷后可能丢失全部会话与持久任务。该项是 **F6 的既定范围**，本轮不擅自添加未测试的备份功能。上线前可采用运营者现有备份系统，并完成至少一次恢复演练。
- 生产部署需要 HTTPS、强口令、访问限制、通知凭据与数据库数据卷保护。模型费率为零值占位，**不代表调用免费**；在完成 F5 之前需通过中转或供应商平台进行预算控制。
- 还需人工验收：真实模型工具调用、微信扫码/收发、真实飞书响应、Obsidian 只读挂载、移动端 UI、Docker 重启与存储备份恢复。

## 推荐的冻结准则

1. PR #4 / #5 / #6 的 GitHub CI 全绿，当前所知可复现缺陷有回归用例。
2. 三个 PR 继续按用户指定顺序独立验收，未获批准不提前合并；PR #6 是基于 PR #5 的堆叠分支。
3. 本次收尾后冻结新需求 F4～F6，以及其他知识库写入、模型路由和多 Agent 调度功能。
4. 线上未验收之处用“待验证”标识，不宣称实际投递或生产容灾已完成。

**总判断：**日常单用户试用架构基本成立；带真实财务/私人知识库资料的长期公开服务仍需备份、权限、成本和现实环境验证。缺少这些条件时，不能宣布“完全没有致命风险”。
