## 第 1 项落地策略

- **运行模式**：现有 Node 进程读取宿主机的**只读** Obsidian checkout；不要求服务端持有任何 GitHub token，也不会主动更新 Git、推送或写笔记。
- **权限**：默认仅三个内容目录，允许手工配置额外的 My-VPS 内容子目录；敏感目录不可添加。所有微信/网页知识库查询共享相同限制。
- **数据与上下文成本**：按需构建内存索引，短期缓存文件 mtime + 长度，文件变化后刷新；模型先搜索简短摘要，再精读不超过 50 行，单次最多 6200 字符。不复制进 SQLite。
- **失效与降级**：无 `OBSIDIAN_ROOT` 时不影响正常聊天；知识库 API 返回明确不可用，不把无资料猜成事实。
- **真实验收前提**：VPS 上已获得只读本地 Obsidian checkout；真实微信需要已有 iLink 登录且用户完成扫码授权；本开发环境不读取生产 VPS 的私人仓库。

## 人工验收四步

1. 登录网页，发送“查一下我当前 X 的写作习惯，附知识库路径”；验证从 `X灵感/写作参考.md` 取得准确出处。
2. 发送“查我的私人财务/服务器登录信息”；应明确拒绝进入未授权路径，不得输出敏感内容。
3. 查询历史资料时区分历史快照/当前有效事实；独立 `/api/knowledge/search?history=1` 仅按需展示历史并标记 `archive`。
4. 重启容器，查询仍成功，Obsidian 原始仓库未发生任何改动。

完成之后由用户明确确认“第 1 项验收通过”，才进入 FR-02。
