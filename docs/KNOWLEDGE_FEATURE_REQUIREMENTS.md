# v4 知识库驱动的个人 Agent：候选功能需求

> 状态：需求草案，**尚未实现**。基于 2026-10-10 对私有 Obsidian `xiaomoBoy/Obsidian` 的目录与重点文件抽查形成。这里定义的是 **Pi Durable 产品功能**，而不是要求增加五类 Obsidian 笔记。实施须沿用现有单用户、SQLite、原生 ESM 和 Durable Runtime；微信只是可选的输入/输出 Channel。

## 产品目标与边界

当前 Pi Durable 已有持久任务、会话、提醒、子 Agent、网页及微信 iLink 通道。下一阶段从“能办事”升级为“**能在允许的知识范围内理解已有资料、收集一手证据，并交付可追溯的结果**”。

Obsidian 已是个人事实/策略的权威来源，不在 Pi Durable 再建第二套真相库。新增 SQLite 文档只保存索引、任务状态、草稿、审批和投递队列；权威内容继续按 `Obsidian/AGENTS.md`、`AI工作路由.md` 和各目录规则维护。任何自动分析结果都不得冒充本人确认的事实。

## FR-01｜Obsidian 定向查询与来源引用（P0）

**用户故事**：在网页或已绑定微信里说“我目前的 X 写作规则是什么”“找我以前写过的 Pi Durable 内容”，Agent 查私有 Obsidian 并给出链接/路径，而不是凭模型记忆编造。

**功能**
- 支持**只读本地仓库目录**作为首选数据源；以后按需增加使用最小只读权限的 GitHub 数据源。不能假定聊天中已连接的 GitHub 工具能自动在 VPS 上使用。
- 初始默认只允许内容类路径：`My-VPS/我的VPS/AI学习/`、`My-VPS/我的VPS/X灵感/`、`My-VPS/我的VPS/VPS小白教程/`；其他目录需显式加入读取白名单。个人档案、财务、服务器资产、密钥相关目录默认禁检索、禁微信返回。
- 读取根及相关目录 `AGENTS.md`、`_index.md` 和当前活文件；区分归档/历史快照、当前状态、待核查。以路径 + 片段 + 源修改标识输出可核对的引用，不能把检索摘要写成权威事实。
- 使用**按需检索 + 小片段注入**（先文件名/目录/关键词，再精读），不把整库塞进模型上下文。索引为可重建缓存，源更新后增量刷新；查不到时明确表示未找到。

**验收**
1. 用户问 X 现行写作习惯，返回来自 `X灵感/写作参考.md` 的答案并附准确源路径。
2. 用户问当前副业状态但未授权读取 `my-info/`，明确拒绝检索受限范围，而不是偷偷扩展白名单。
3. 归档旧战略与现行战略冲突时，不能把旧文结论当作现行决定。
4. SQLite 删除可重建索引后仍能从原 Obsidian 恢复，不更改原文。

## FR-02｜一句话捕获想法 + 记忆候选审批（P0）

**用户故事**：通过微信说“记一下：Pi 接微信最好保持独立 Channel”，系统保存**用户原话、时间、出处和上下文**，作为可审核的长期知识候选；不直接篡改 Obsidian 的已确认事实。

**功能**
- 新增 `capture_note` / “记下来”意图：原文优先，AI 分类仅作建议；支持想法、经验、待办、决策候选四类，不保存整个聊天流水。
- 短信息先写 Durable 持久队列，允许网页查看、修改、确认、驳回；微信端可收到一个简短确认结果，审批动作也必须绑定已授权身份。
- 按知识库协议：跨 AI 对账/推断候选默认只进入 `资料库/AI记忆同步/对账记录.md` 的待确认区；用户逐项批准目标位置后才写回其他权威文件。仅用户当次明确指名保存位置和成品时，依其目录规则处理。
- 写回时记录来源类型（本人原话、本人确认、AI 整理、AI 推断）、时间和 `source_ref`，校验最新 Git 状态、目标目录规则与是否重复；不在微信或日志泄露原始凭据。
- 未配置 Obsidian 写权限时仍可保留本地待审候选，但不得显示“已写入知识库”。

**验收**
1. “记下这个想法”产生一条可恢复的待确认卡片，完整保留原话。
2. 未批准不能改变 `my-info/`、`agent-memory/` 或 `My-VPS/` 活文件。
3. 同一微信消息重放或进程崩溃重启不生成两条候选。
4. 批准/驳回均保留简短操作记录，明确成功、冲突或失败；敏感内容命中禁写规则时拒绝写回。

## FR-03｜技术实测与项目变更证据卡（P1）

**用户故事**：让 Agent “记录这次 Pi Durable 的微信集成测试”，自动关联任务、GitHub PR/提交和可用测试输出，生成能复查的技术记录。

**功能**
- 为有代表性的任务保存一张**证据卡**：研究问题、版本/模型/配置摘要、运行条件、实验步骤、观察结果、失败和修复、原始证据链接、复验状态。
- 自动引用已有 Durable Task ID、会话、时间、测试日志摘要及显式提供的 PR/commit；只有 API 实际返回时才记录 Token、缓存命中、费用、耗时，不推算或捏造测量值。
- 支持“从本次任务生成复盘草稿”，人工确认后**链接到**已有 GitHub 仓库/Obsidian 相应文章；不复制整个代码仓库、不要求每个任务写复盘。
- 明确区分 **模拟测试、CI 成功、真实外部端到端验收** 三种证据等级。

**验收**
1. 模拟 `faux` 测试只能标注为模拟；未经扫码不能标注“微信真实收发已验证”。
2. 能从任务/PR 反查一次失败、修复、验收的时间线。
3. 重启后证据卡可继续完善，不重复自动生成；手动归档后不再提醒。

## FR-04｜X 创作助手：选题查重 + 证据驱动写作（P1）

**用户故事**：在微信说“我想写 Pi 的缓存命中率，之前发过吗？”或“参考我的 X 风格写一篇 200 字左右的短推”。

**功能**
- 只读接入现有 `X灵感/_index.md`、`已发选题账.md`、`高互动样本.md`、`写作参考.md`、`X 写作风格分类.md` 和按需选择的 `X数据分析/` 文件；不重建一套选题池。
- 查重输出“同题已发/切口相似/尚无明确证据”，附已有帖子和来源链接；不能把“库内未收录”认定为“肯定没发”。
- 草稿按内容类型使用相应本人确认规则：热点/福利短帖、Pi 插件或作者分点帖、真实实操帖；对未确认的风格不能声称“本人偏好”。附可核实事实来源，产品当前状态需要实时核验时另行标注。
- 草稿留在当前任务/会话；**不自动发布 X**，也不自动更改“已发选题账”，除非用户明确确认实际已发及发布链接。

**验收**
1. 输入一个已发 Pi Durable 题材时给出至少一条来源、说明重复角度。
2. 写作助手能按所选 X 文章类型输出草稿，但不把写作风格应用到普通技术问答。
3. 没有发布链接时不得将草稿标记为“已发”；X 外部平台连接失败不阻塞本地草稿能力。

## FR-05｜用户反馈与商业机会轻量关联（P2）

**用户故事**：把读者提出的问题或合作需求转发给 Agent，系统记录“哪个内容引来了什么问题/机会、最后是否解决或成交”，帮助决定下次写什么。

**功能**
- 只收集**主动转发/手动指定**的 X 评论、读者反馈、合作线索及已知帖子链接；不声称 iLink 可以监听所有个人微信消息，不默认抓取社交私信。
- 同一反馈可关联 X 已发帖子 ID、主题、已采取动作和真实结果；合并重复问题，标记是否值得写教程或修复项目。
- 商业状态区分“咨询/报价/合作中/已到账/关闭”；已到账金额只引用 `my-info/我的信息/副业经营/副业数据中心.md` 的权威记录，禁止第二本收入流水。默认仅显示匿名摘要，不把隐私/商务内容推送到群聊。
- 每周或手动生成**最多 5 条高信号摘要**；默认不推送普通反馈，只有用户主动订阅或出现明确异常才通知。

**验收**
1. 同一问题来自多条转发时可合并，并追溯原始来源。
2. 只有“洽谈中”不能生成“成交”或“到账”结论。
3. 关闭网页、重启后线索关联与状态不丢；群聊和未授权微信身份不可读取商务摘要。

## 共用非功能性约束

- **单用户优先、最小化复杂度**：尽量复用现有 `server.mjs`、`lib/` ESM、Durable Documents/Tasks、SQLite、Webhook / WeChat 通道，不预设多租户、消息总线、大型向量数据库或新的前端框架。
- **权限与数据隔离**：网页 Basic Auth 不等于知识库授权；微信 Channel 须校验具体授权身份和可访问范围。默认不在微信暴露财务、健康、家庭及服务器资产。
- **确定性和可恢复**：外部写入、审批、投递应有稳定 `requestId`、明确状态、失败重试/冲突处理；不能把“至少一次投递”说成端到端恰好一次。
- **人机分工**：查询可自动，候选可自动，改变权威事实、外部发布及高影响操作必须符合目录规则与用户审批。
- **节制成本**：索引只收可访问路径；增量刷新、按需读取、短上下文证据片段；不把全库 1000 多篇逐轮放进模型。

## 依赖与实施顺序

| 阶段 | 需求 | 最小交付 | 决策门槛 |
| --- | --- | --- | --- |
| v4-A | FR-01 | 白名单只读检索、源引用、微信与网页查询 | 先证明能准确区分活文件/归档和授权目录 |
| v4-B | FR-02 | Durable 候选 Inbox、网页审批、遵循唯一源的可选写回 | 检查写回冲突、重复提交和越权访问 |
| v4-C | FR-03 | 实验/项目证据卡与任务/PR 链接 | 明确实际测试证据等级；无自动测量则留空 |
| v4-D | FR-04 | X 查重与定向草稿 | 用已有已发选题样本回归，人工核验 |

**非本轮范围**：真实微信扫码验收（独立于这些新需求）、图片/文件内容理解、自动发布 X、全量镜像 Obsidian、全量邮件/微信抓取、自动写财务流水、语义推断直接改持久记忆。上述功能都不在本文件中假定已完成。

## 建议的首轮演示

1. 微信上问“我写过哪些 Pi Durable 文章？给我路径”，只返回白名单内容 + 准确引用。
2. 微信上说“记一下：微信 Channel 要和 Durable Runtime 解耦”，产生一个待确认项；网页端审核后再写到规则允许的位置。
3. 重启 Pi Durable 并重复发送消息：候选不重建两条，历史查询和记录都保留。

首轮只验收 FR-01 / FR-02；FR-03～05 保留为设计需求，不预先创造维护成本。
